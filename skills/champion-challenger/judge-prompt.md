# 審判の手順

審判は `judge.sh` で動かす。審判には、案の名前・経緯と、どちらが現行かを**伝えない**。

## 呼び出し

```bash
<skill のディレクトリ>/judge.sh <プロンプトファイル> [モデル ID]
```

- プロンプトは**ファイルに書いて stdin で渡す**。引数に埋めない
- モデルと effort（Haiku 5.5 / medium）は `judge.sh` 内で固定されている。変えられるのは第2引数のモデル ID のみ
- 画像などのファイルを読ませるときは、`JUDGE_TOOLS=Read <skill のディレクトリ>/judge.sh ...` で呼ぶ。既定はツールなし
- 標準出力は JSON 1行: `{winner, reason, loser_weakness, loss_kind, unverified?, cost_usd}`
- 失敗したときは `judge.sh` が1回やり直す。やり直しでも失敗した場合は終了コード1を返すので、ログに残す

## 順序を入れ替える判定

LLM の審判は案を並べる順序に影響されるので、順序を入れ替えて2回判定する。2つは独立なので並列で呼ぶ。

1. プロンプトA: 案X=チャンピオン、案Y=チャレンジャー
2. プロンプトB: 案X=チャレンジャー、案Y=チャンピオン
3. 両方でチャレンジャーが勝った場合のみチャレンジャーの勝ちとする。判定が分かれた場合、両方でチャンピオンが勝った場合、`draw` の場合、失敗した場合はチャンピオン維持とする

## プロンプトに入れるもの

- 目的文と判定基準（観点。重要な順に並べる）
- 比較条件
- 案X・案Yの本文（短ければ直接、長ければ読ませるファイルのパス。画像はパスのみ）
- 「基準で差がつかない、または差が表現の違いだけなら、勝者をつけず draw とする。」の一文
- ツールなしのとき: 「ツールは使わず、この文面だけで判断する」の一文
- `JUDGE_TOOLS=Read` のとき: 「画像は Read ツールで読んで判断する」の一文

出力形式はスキーマで強制されるので、プロンプトに形式の指示は書かない。

## 出力の意味

| フィールド | 内容 |
| --- | --- |
| winner | `X` / `Y` / `draw` |
| reason | 決め手 |
| loser_weakness | 負けた側の弱点 |
| loss_kind | `policy`（方針の問題）/ `tunable`（調整で直せる） |
| unverified | 測っていないこと（任意） |

## 扱い

- `loser_weakness` はログの「敗因・学び」に転記し、次のチャレンジャー生成の入力にする
- reason には案に書かれていない根拠が混じることがある。勝敗は順序を入れ替えた2回の結果で見て、理由は参考にとどめる
- 審判の出力は要約のみメインエージェントに戻し、全文は貼らない
